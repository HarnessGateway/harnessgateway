HarnessGateway {{ .Chart.AppVersion }} is starting in {{ .Release.Namespace }}; boxes run in {{ include "hg.boxesNamespace" . }}.

1. Wait for it:
     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "hg.fullname" . }}-worker

   The worker proves at start-up that the gVisor RuntimeClass "{{ .Values.boxes.runtimeClassName }}" exists and that a box pod reaches
   the door and nothing else. If it keeps restarting, its log says which check failed:
     kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "hg.fullname" . }}-worker

2. Create the organization and its first admin (once; it prints the admin's invitation link and an admin key):
     kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "hg.fullname" . }}-api -- harnessgateway init --admin-email you@example.com

3. Open the console{{ if not .Values.ingress.enabled }}:
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "hg.fullname" . }}-console 8800:{{ .Values.console.service.port }}
   and the api:
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "hg.fullname" . }}-api 8000:{{ .Values.api.service.port }}
{{- else }} at http://{{ .Values.ingress.console.host }} and the api at http://{{ .Values.ingress.api.host }}{{ end }}

Invitation links are built on console.url ({{ .Values.console.url }}).
{{- if not .Values.secrets.existingSecret }}
The platform's keys are in the Secret {{ include "hg.fullname" . }}; it is kept on uninstall. Back it up with the database:
without the secret key no organization's data can be opened.
{{- end }}
